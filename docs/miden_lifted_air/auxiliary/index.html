Auxiliary trace types: builder and cross-AIR identity checking.

§Protocol Overview

The auxiliary trace enables cross-AIR buses (multiset / logup) in the lifted STARK.

§Prover

  1. AuxBuilder::build_aux_trace constructs the aux trace and returns aux values (extension-field elements whose meaning is AIR-defined).
  2. The aux trace is committed (Merkle commitment).
  3. Aux values are sent via the Fiat-Shamir transcript.

§AIR constraints (eval)

  1. The AIR defines how aux values relate to the committed aux trace. A common pattern is to constrain them to equal the aux trace’s last row, but the protocol does not impose this — the AIR is free to define whatever relationship it needs.
  2. Transition constraints enforce the aux trace’s internal logic (e.g. running product accumulation).

§Verifier

  1. The verifier receives aux values from the transcript.
  2. Constraint evaluation (steps 4–5) is checked at a random point.
  3. reduced_aux_values computes each AIR’s bus contribution from the aux values, challenges, and public inputs.
  4. Global check: all contributions combine to identity (prod=1, sum=0).
