1//! # DEEP Quotient for Lifted FRI
2//!
3//! DEEP converts evaluation claims into a low-degree test. Given W committed polynomials
4//! `{fᵢ}` and claimed evaluations `fᵢ(zⱼ) = vᵢⱼ`, the quotient
5//!
6//! ```text
7//! Q(X) = Σⱼ βʲ · Σᵢ αᵂ⁻¹⁻ⁱ · (vᵢⱼ - fᵢ(X)) / (zⱼ - X)
8//! ```
9//!
10//! is low-degree iff all claims are correct. A false claim creates a pole, detectable by FRI.
11//!
12//! ## Design Choices
13//!
14//! **Uniform opening points.** All columns share the same opening points `{zⱼ}`. This enables
15//! factoring out `f_reduced(X) = Σᵢ αᵂ⁻¹⁻ⁱ·fᵢ(X)`, so the verifier computes one inner
16//! product per query rather than one per column per point.
17//!
18//! **Two challenges.** Separating α (columns) from β (points) improves soundness. With a
19//! single challenge, a cheating prover must avoid collisions among k·m terms; with two,
20//! only k+m terms matter. This costs one extra field element in the transcript.
21//!
22//! **Lifting.** Polynomials of degree d on domain D embed into a larger domain D* via
23//! `f(X) ↦ f(Xʳ)` where r = |D*|/|D|. In bit-reversed order, this means each evaluation
24//! repeats r times consecutively—implemented by virtual upsampling without data movement.
25//!
26//! **Verifier's view of lifting.** From the verifier's perspective, all polynomials
27//! appear to be evaluated at the same point z on the same domain. The prover computes
28//! `fᵢ(zʳ)` for degree-d polynomials, but this equals `fᵢ'(z)` where `fᵢ'(X) = fᵢ(Xʳ)`
29//! is the lifted polynomial. This uniformity enables the `f_reduced` factorization.
30//!
31//! ## Preconditions (caller responsibility)
32//!
33//! The DEEP constructors assume all opening points are valid: distinct and outside the
34//! trace subgroup `H` and the LDE evaluation coset `gK`. Invalid points can trigger
35//! division by zero in the barycentric weights. In practice, the outer STARK protocol
36//! is expected to enforce this before invoking DEEP.
37//!
38//! ## Random Linear Combination Convention
39//!
40//! The batching challenge `α` reduces W columns via Horner evaluation:
41//! `f_reduced = horner(α, [f₀, f₁, ..., fᵂ₋₁])`, where columns are flattened
42//! across groups and matrices in commitment order. The `horner` function assigns
43//! the highest power to the first element: `f₀·αᵂ⁻¹ + f₁·αᵂ⁻² + ... + fᵂ₋₁·α⁰`.
44//!
45//! This convention is shared by:
46//! - Prover OOD reduction (`horner` over aligned batched evals)
47//! - Verifier OOD reduction (inline in `verifier::DeepOracle::new` via `horner_acc`)
48//! - Verifier query-time row reduction (`verifier::DeepOracle::open_batch` via `horner_acc`)
49//! - Prover LDE evaluation (`prover::DeepPoly::from_trees` via explicit dot-product with reversed
50//!   negated coefficients — see comments there)

74/// Read OOD evaluation matrices from a verifier channel.
75///
76/// The prover sends one flat slice per evaluation point containing all matrices'
77/// column values concatenated. This function splits by widths and reshapes into
78/// per-group, per-matrix `RowMajorMatrix<EF>` with `num_eval_points` rows each.
79pub fn read_eval_matrices<F, EF, Ch>(
80    group_widths: &[&[usize]],
81    num_eval_points: usize,
82    channel: &mut Ch,
83) -> Result<OpenedValues<EF>, TranscriptError>
84where
85    F: TwoAdicField,
86    EF: ExtensionField<F>,
87    Ch: VerifierChannel<F = F>,
88{
89    let all_widths: Vec<usize> = group_widths.iter().flat_map(|gw| gw.iter().copied()).collect();
90    let total_width: usize = all_widths.iter().sum();
91
92    let mut values: Vec<Vec<EF>> =
93        all_widths.iter().map(|&w| Vec::with_capacity(w * num_eval_points)).collect();
94
95    for _ in 0..num_eval_points {
96        let flat = channel.receive_algebra_slice::<EF>(total_width)?;
97        let mut offset = 0;
98        for (m, &w) in all_widths.iter().enumerate() {
99            values[m].extend_from_slice(&flat[offset..offset + w]);
100            offset += w;
101        }
102    }
103
104    let mut mat_iter = values
105        .into_iter()
106        .zip(&all_widths)
107        .map(|(vals, &w)| RowMajorMatrix::new(vals, w));
108    let evals = group_widths
109        .iter()
110        .map(|gw| mat_iter.by_ref().take(gw.len()).collect())
111        .collect();
112
113    Ok(evals)
114}
