1//! Lifted Matrix Commitment Scheme (LMCS) for matrices with power-of-two heights.
2//!
3//! This module provides a Merkle tree commitment scheme for matrices that store
4//! polynomial evaluations over multiplicative cosets. The tree is indexed by
5//! **domain order** (natural index): callers address leaves by domain index,
6//! and bit-reversal concerns are encapsulated inside the LMCS.
7//!
8//! # Main Types
9//!
10//! - [`config::LmcsConfig`]: Configuration holding cryptographic primitives (sponge + compression)
11//!   with packed types for SIMD parallelization.
12//! - [`Lmcs`]: Trait for LMCS configurations, providing type-erased access to commitment
13//!   operations.
14//! - [`LmcsTree`]: Trait for built LMCS trees, providing opening operations.
15//! - `lifted_tree::LiftedMerkleTree`: The underlying Merkle tree data structure.
16//! - [`proof::Proof`]: Single-opening proof with rows, optional salt, and authentication path.
17//! - [`proof::BatchProof`]: Batch opening data with Merkle witness for path extraction.
18//!
19//! # Mathematical Foundation
20//!
21//! Consider a polynomial `f(X)` of degree less than `d`, and let `g` be the coset generator and
22//! `K` a subgroup of order `n ≥ d` with primitive root `ω`. The coset evaluations
23//! `{f(g·ω^j) : j ∈ [0, n)}` can be stored in two orderings:
24//!
25//! - **Canonical order**: `[f(g·ω^0), f(g·ω^1), ..., f(g·ω^{n-1})]`
26//! - **Bit-reversed order**: `[f(g·ω^{bitrev(0)}), f(g·ω^{bitrev(1)}), ..., f(g·ω^{bitrev(n-1)})]`
27//!
28//! where `bitrev(i)` is the bit-reversal of index `i` within `log2(n)` bits.
29//!
30//! # Lifting by Upsampling
31//!
32//! When we have matrices with different heights n₀ ≤ n₁ ≤ … ≤ nₜ₋₁ (each a power of two),
33//! we "lift" smaller matrices to the maximum height N = nₜ₋₁ using **nearest-neighbor
34//! upsampling**: each row is repeated contiguously `r = N/n` times.
35//!
36//! For a matrix of height `n` lifted to `N`, the index map is: `i ↦ floor(i / r) = i >> log2(r)`
37//!
38//! **Example** (`n=4`, `N=8`):
39//! - Original rows: `[row0, row1, row2, row3]`
40//! - Upsampled: `[row0, row0, row1, row1, row2, row2, row3, row3]` (blocks of 2)
41//!
42//! # Why Upsampling Works
43//!
44//! Given evaluations of `f(X)` over a coset, upsampling to height `N = n · r` (where `r = 2^k`)
45//! produces evaluations of the lifted polynomial `f'(X) = f(Xʳ)` over the larger coset.
46//!
47//! The internal hashing uses matrices whose rows are in bit-reversed order (as produced by
48//! `BitReversedMatrixView`). For such data, upsampling by nearest-neighbor repetition
49//! (`i >> k`) produces the correct lifted evaluations. The LMCS then bit-reverses the
50//! leaf digest array so the Merkle tree is indexed by domain order.
51//!
52//! # Opening Semantics
53//!
54//! When opening at domain index `d`, the LMCS maps `d` to bit-reversed row index
55//! `bitrev(d) >> k` for each matrix. This returns the same values that were hashed
56//! into Merkle leaf `d`.
57//!
58//! # Equivalence to Cyclic Lifting
59//!
60//! Upsampling bit-reversed data is equivalent to cyclically repeating canonically-ordered data:
61//!
62//! ```text
63//! Upsample(BitReverse(data)) = BitReverse(Cyclic(data))
64//! ```
65//!
66//! where cyclic repetition tiles the original `n` rows periodically: `[row0, row1, ..., row_{n-1},
67//! row0, ...]`.
68//!
69//! This equivalence follows from the bit-reversal identity: for `r = N/n = 2^k`,
70//! `bitrev_N(i) mod n = bitrev_n(i >> k)`.

106/// Trait for LMCS configurations.
107pub trait Lmcs: Clone {
108    /// Scalar field element type for matrix data.
109    ///
110    /// `Send + Sync` bounds required by [`Matrix<F>`].
111    type F: Clone + Send + Sync;
112    /// Commitment type (root hash).
113    type Commitment: Clone + Eq;
114    /// Tree type (prover data), parameterized by stored matrix type.
115    type Tree<Stored: Matrix<Self::F>>: LmcsTree<Self::F, Self::Commitment, Stored>;
116    /// Batch witness type returned by [`read_batch_proof`](Self::read_batch_proof) and
117    /// [`read_lifted_batch_proof`](Self::read_lifted_batch_proof).
118    type BatchProof: BatchProofView<Self::F, Self::Commitment>;
119
120    /// Build a tree from domain-ordered matrices with no transcript padding (alignment = 1).
121    ///
122    /// The LMCS extracts the inner bit-reversed matrices via
123    /// `BitReversibleMatrix::bit_reverse_rows` and stores them. The tree is indexed
124    /// by domain order; [`LmcsTree::leaves`] returns the stored bit-reversed matrices.
125    ///
126    /// This affects only transcript hint formatting; the commitment root is unchanged.
127    fn build_tree<M: BitReversibleMatrix<Self::F>>(&self, leaves: Vec<M>) -> Self::Tree<M::BitRev>;
128
129    /// Build a tree from domain-ordered matrices using the hasher alignment for transcript
130    /// padding.
131    ///
132    /// Rows are padded to the hasher's alignment when streaming hints.
133    /// When the alignment is 1, this is identical to [`Self::build_tree`].
134    fn build_aligned_tree<M: BitReversibleMatrix<Self::F>>(
135        &self,
136        leaves: Vec<M>,
137    ) -> Self::Tree<M::BitRev>;
138
139    /// Hash a sequence of field slices into a leaf hash.
140    ///
141    /// Inputs are absorbed in order. For salted leaves, append the salt slice to the
142    /// iterator (or call this with a chained iterator).
143    fn hash<'a, I>(&self, rows: I) -> Self::Commitment
144    where
145        I: IntoIterator<Item = &'a [Self::F]>,
146        Self::F: 'a;
147
148    /// Compress two hashes into their parent (2-to-1 compression).
149    fn compress(&self, left: Self::Commitment, right: Self::Commitment) -> Self::Commitment;
150
151    /// Open an exact batch proof by reading hint data from a transcript channel.
152    ///
153    /// The hint format is implementation-defined; callers must use the matching
154    /// exact [`LmcsTree::prove_batch`] implementation to produce compatible hints.
155    /// `widths` must match the committed tree (including any alignment padding
156    /// if `build_aligned_tree` was used), and `indices` must already be in the
157    /// committed tree's own index space.
158    ///
159    /// # Preconditions
160    /// - `indices` must be non-empty.
161    /// - `indices.depth()` must be the committed tree depth.
162    ///
163    /// # Postconditions
164    /// On success, the returned map is keyed by the exact tree indices — one
165    /// entry per unique index. Each entry's `RowList<F>` has one row per width
166    /// in `widths`, with that row's length matching the corresponding width.
167    fn open_batch<Ch>(
168        &self,
169        commitment: &Self::Commitment,
170        widths: &[usize],
171        indices: &TreeIndices,
172        channel: &mut Ch,
173    ) -> Result<OpenedRows<Self::F>, LmcsError>
174    where
175        Ch: VerifierChannel<F = Self::F, Commitment = Self::Commitment>;
176
177    /// Open a virtually lifted batch proof.
178    ///
179    /// `query_indices` live in the query domain. They are projected to
180    /// `tree_log_height`, opened with [`Self::open_batch`], then expanded back to the
181    /// original query indices. The returned map is keyed by the original query
182    /// indices, so callers can reduce all commitment groups uniformly.
183    ///
184    /// Returns [`LmcsError::InvalidProof`] if `tree_log_height > query_indices.depth()`.
185    fn open_lifted_batch<Ch>(
186        &self,
187        commitment: &Self::Commitment,
188        widths: &[usize],
189        query_indices: &TreeIndices,
190        tree_log_height: u8,
191        channel: &mut Ch,
192    ) -> Result<OpenedRows<Self::F>, LmcsError>
193    where
194        Ch: VerifierChannel<F = Self::F, Commitment = Self::Commitment>,
195    {
196        let leaf_indices = query_indices.fold_to_depth(tree_log_height)?;
197        let rows_by_leaf = self.open_batch(commitment, widths, &leaf_indices, channel)?;
198        query_indices.expand_leaf_values(tree_log_height, &rows_by_leaf)
199    }
200
201    /// Parse an exact batch opening from transcript hints without verification.
202    ///
203    /// Reads leaf openings and sibling hashes from the channel, hashes leaves,
204    /// and reconstructs the Merkle witness. Does not verify against a commitment;
205    /// validation happens in [`open_batch`](Lmcs::open_batch). The returned
206    /// witness and openings are keyed by the exact tree indices, because Merkle
207    /// paths are defined for leaves of the actual tree.
208    ///
209    /// Use [`merkle_witness::MerkleWitness::path`] on the returned witness to extract
210    /// authentication paths.
211    fn read_batch_proof<Ch>(
212        &self,
213        widths: &[usize],
214        indices: &TreeIndices,
215        channel: &mut Ch,
216    ) -> Result<Self::BatchProof, LmcsError>
217    where
218        Ch: VerifierChannel<F = Self::F, Commitment = Self::Commitment>;
219
220    /// Parse a virtually lifted batch opening from transcript hints.
221    ///
222    /// `query_indices` are projected to `tree_log_height`, then parsed with
223    /// [`Self::read_batch_proof`]. The returned proof is the same `BatchProof`
224    /// type as the exact parser and remains keyed by projected tree indices.
225    ///
226    /// Returns [`LmcsError::InvalidProof`] if `tree_log_height > query_indices.depth()`.
227    fn read_lifted_batch_proof<Ch>(
228        &self,
229        widths: &[usize],
230        query_indices: &TreeIndices,
231        tree_log_height: u8,
232        channel: &mut Ch,
233    ) -> Result<Self::BatchProof, LmcsError>
234    where
235        Ch: VerifierChannel<F = Self::F, Commitment = Self::Commitment>,
236    {
237        let leaf_indices = query_indices.fold_to_depth(tree_log_height)?;
238        self.read_batch_proof(widths, &leaf_indices, channel)
239    }
240
241    /// Get the alignment used by `build_aligned_tree`.
242    ///
243    /// This is the hasher's rate, used to pad rows when streaming hints.
244    fn alignment(&self) -> usize;
245}

247/// Trait for built LMCS trees.
248///
249/// Provides methods for accessing tree data and generating proofs.
250pub trait LmcsTree<F, Commitment, M> {
251    /// Get the tree root (commitment).
252    fn root(&self) -> Commitment;
253
254    /// Get the height of the largest matrix (i.e. the number of leaves of the Merkle tree).
255    fn height(&self) -> usize;
256
257    /// Get references to the committed matrices.
258    ///
259    /// Matrix widths are not padded; use [`Self::aligned_widths`] for aligned widths.
260    fn leaves(&self) -> &[M];
261
262    /// Get the opened rows for a given leaf index (original matrix widths, no padding).
263    fn rows(&self, index: usize) -> RowList<F>;
264
265    /// Get the opened rows for a given leaf index, padded to the tree's alignment.
266    ///
267    /// Padding uses `Default::default()` and is not enforced by verification.
268    fn aligned_rows(&self, index: usize) -> RowList<F>;
269
270    /// Column alignment used when streaming openings.
271    fn alignment(&self) -> usize;
272
273    /// Get widths for each committed matrix (original, no padding).
274    fn widths(&self) -> Vec<usize>;
275
276    /// Get aligned widths for each committed matrix (padded to alignment).
277    fn aligned_widths(&self) -> Vec<usize> {
278        let alignment = self.alignment();
279        self.widths().into_iter().map(|w| aligned_len(w, alignment)).collect()
280    }
281
282    /// Prove an exact batch opening and stream it into a transcript channel.
283    ///
284    /// The hint format is implementation-defined and must be consumed by the
285    /// corresponding exact `Lmcs::open_batch` implementation. Rows are padded to
286    /// the tree's alignment before being written to the channel. `indices` must
287    /// already be in this tree's own index space.
288    ///
289    /// Leaf openings are written in **sorted tree index order** (ascending, deduplicated).
290    fn prove_batch<Ch>(&self, indices: &TreeIndices, channel: &mut Ch)
291    where
292        Ch: ProverChannel<F = F, Commitment = Commitment>;
293
294    /// Prove a virtually lifted batch opening.
295    ///
296    /// Projects `query_indices` to this tree's depth and then delegates to exact
297    /// [`Self::prove_batch`].
298    fn prove_lifted_batch<Ch>(&self, query_indices: &TreeIndices, channel: &mut Ch)
299    where
300        Ch: ProverChannel<F = F, Commitment = Commitment>,
301    {
302        let tree_log_height = miden_lifted_air::log2_strict_u8(self.height());
303        let leaf_indices = query_indices
304            .fold_to_depth(tree_log_height)
305            .expect("query index depth must be at least the committed tree depth");
306        self.prove_batch(&leaf_indices, channel);
307    }
308}
